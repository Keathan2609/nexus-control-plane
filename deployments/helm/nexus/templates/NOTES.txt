{{- if not .Values.secrets.create }}

  ACTION REQUIRED - credentials
  ------------------------------------------------------------------------------------
  This release expects a pre-existing Secret named "{{ .Values.secrets.existingSecret }}".
  Every pod will stay in CrashLoopBackOff until it exists. Check with:

    kubectl -n {{ .Release.Namespace }} get secret {{ .Values.secrets.existingSecret }}

  If it does not exist yet, the recommended path is External Secrets Operator or Sealed
  Secrets. For a quick non-production bootstrap:

    kubectl -n {{ .Release.Namespace }} create secret generic {{ .Values.secrets.existingSecret }} \
      --from-literal=NEXUS_DATABASE_URL='postgres://user:pass@host:5432/nexus?sslmode=require' \
      --from-literal=NEXUS_AUTH_JWT_SECRET="$(openssl rand -base64 48)" \
      --from-literal=NEXUS_WEBHOOK_SECRET="$(openssl rand -hex 32)"
{{- end }}

{{- if .Values.secrets.create }}

  NOTE - credentials are in the release
  ------------------------------------------------------------------------------------
  secrets.create=true, so the values you passed are stored in the Helm release Secret in
  plain text, and are likely in your shell history and CI logs too. That is fine for a
  laptop cluster and not fine for anything shared. Switch to secrets.create=false with an
  externally managed Secret before this reaches a real environment.
{{- end }}

{{- if not .Values.postgresql.enabled }}

  Database: external (postgresql.enabled=false).
  The DSN comes from NEXUS_DATABASE_URL in the Secret above. Nothing in this chart
  provisions or backs up your database.
{{- else }}

  Database: bundled StatefulSet (postgresql.enabled=true).
  No backups, no PITR, no failover. This is an evaluation setup - move to a managed
  instance or an operator before storing anything you would miss.
{{- end }}

{{- if .Values.migrations.enabled }}

  Migrations run as a Job at sync-wave -1 (before the API). Watch it with:
    kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/component=migration --tail=100
{{- else }}

  Migrations are DISABLED (migrations.enabled=false). If your database schema is not
  managed elsewhere, the API will fail against an empty or stale schema. Confirm the
  migrate entrypoint your nexus-api image exposes, set migrations.args to match, then
  enable it.
{{- end }}

{{- if not .Values.networkPolicy.enabled }}

  NetworkPolicy is disabled. Nothing restricts which pods in this namespace can reach the
  database. Once you have confirmed your CNI enforces NetworkPolicy, set
  networkPolicy.enabled=true and verify with a deliberate connectivity test - a policy your
  CNI silently ignores reads as protection in review and provides none at runtime.
{{- end }}

{{- if and .Values.worker.autoscaling.enabled (gt (int .Values.worker.terminationGracePeriodSeconds) 300) }}

  Heads up: worker autoscaling is on with a {{ .Values.worker.terminationGracePeriodSeconds }}s termination grace period.
  Every scale-down commits a pod for up to that long while it drains an in-flight job.
  Make sure the HPA scaleDown stabilization window is comfortably larger, or the autoscaler
  will keep issuing scale decisions against pods that have not finished leaving yet.
{{- end }}
